# Быстрый ППОП и RFE на линейной регрессии: как устроены и почему без Ridge нельзя

Подробное объяснение двух методов отбора признаков в спектроскопической задаче 6P. Код: `src/models/linear_selection.py` (классы `LinearPPOP`, `LinearRFE`), запуск — `run_6p_linear_selection_per_ion.py`, проверки — `tests/test_linear_selection.py`. Медленный общий ППОП для любых моделей остался в `src/models/feature_selection.py` (`TrueBackwardFeatureSelection`).

Оба метода только **строят рейтинг признаков**. Итоговая модель — одновыходной персептрон: он обучается на первых k признаках рейтинга, и по нему строится кривая R² на test от k.

---

## 1. Данные: сколько признаков и примеров

Файл-кэш: `experiments/6p_full_patience300/xy_cv1.npz`, матрица X размера 3125 × 5427 и 6 целей.

**Признаки.** 5427 каналов матрицы возбуждения–испускания (EEM):

| | Значения | Сколько |
|---|---|---|
| Длина волны возбуждения | 280, 285, …, 410 нм (шаг 5) | 27 |
| Длина волны испускания | 375, 376, …, 575 нм (шаг 1) | 201 |
| Всего каналов | имя вида `E350_em451` | 27 × 201 = **5427** |

**Цели.** 6 концентраций: Cu, Ni, Al, Co, Cr, NO3. Каждый ион отбирается и обучается **отдельно**, со своим рейтингом. Дисперсия на train: около 4.5 у катионов, 136 у NO3.

**Выборки.** Строки идут подряд, разбиение задано порядком строк:

| Выборка | Строки | Примеров | Признаков |
|---|---|---|---|
| train | 0 … 2224 | **2225** | 5427 |
| validation | 2225 … 2824 | **600** | 5427 |
| test | 2825 … 3124 | **300** | 5427 |
| всего | | 3125 | |

При 5-fold кросс-валидации внутри train каждый фолд — это **1780** строк на обучение и **445** на оценку (2225 / 5 = 445).

Главное соотношение задачи: **признаков 5427, а обучающих примеров 2225**, то есть признаков в 2.4 раза больше. Из этого следует почти всё в разделе 3.

### Какая выборка для чего используется

| Шаг | train | validation | test |
|---|---|---|---|
| RFE (рейтинг по \|β\|) | обучение Ridge | — | — |
| ППОП, режим `--score-on cv` (по умолчанию) | обучение и оценка через 5-fold | — | — |
| ППОП, режим `--score-on valid` | обучение | оценка MSE | — |
| Подбор alpha = 700 (`run_6p_ridge_alpha*.py`) | обучение | выбор alpha | — |
| Персептрон на первых k признаках | обучение | ранняя остановка | **итоговый R²** |

Test используется только один раз — для финального R². Режим `cv` хорош тем, что validation не участвует в отборе и остаётся чистой для остановки персептрона. В режиме `valid` тысячи признаков сравниваются на одних и тех же 600 точках, и отбор отчасти подстраивается под их шум. Потом по этой же validation останавливается персептрон, поэтому его метрики на validation получаются завышенными. Test в обоих режимах честный.

## 2. Общая подготовка данных

Перед любым расчётом на обучающей части:

1. **Стандартизация признаков.** Для каждого канала вычитается среднее и делится на стандартное отклонение (ddof = 0), как в `StandardScaler`. Константный канал делится на 1. На оценочной части (фолд CV или validation) используются среднее и std **обучающей** части.
2. **Центрирование y.** Из y вычитается его среднее по обучающей части.

После этого свободный член модели равен среднему y, и модель целиком описывается вектором весов β длины p. Такая модель в точности совпадает с `Pipeline(StandardScaler(), Ridge(alpha))`, а при alpha = 0 — с `LinearRegression`. Это проверяют тесты.

Стандартизация нужна по двум причинам:

- штраф Ridge `alpha·‖β‖²` одинаково относится ко всем каналам только при одинаковом масштабе;
- сравнивать |β| в RFE имеет смысл только при одинаковом масштабе признаков. Иначе канал с маленькими значениями получит большой вес просто из-за единиц измерения.

## 3. Почему честную линейную регрессию без Ridge построить нельзя, а с Ridge можно

### 3.1. Что решает линейная регрессия

МНК ищет веса, минимизирующие ошибку на train:

```text
минимизировать  ‖y − Xβ‖²
```

Приравнивая производную к нулю, получаем **нормальные уравнения**:

```text
XᵀX · β = Xᵀy
```

XᵀX — квадратная матрица p × p (у нас 5427 × 5427). Единственное решение `β = (XᵀX)⁻¹Xᵀy` существует только тогда, когда XᵀX обратима, то есть когда её ранг равен p.

### 3.2. Ранг XᵀX на наших данных

Ранг XᵀX равен рангу X, а ранг X не может быть больше числа строк. После центрирования столбцов каждая строка выражается через остальные (сумма строк равна нулю), поэтому ранг не больше n − 1.

На реальных данных (спектр матрицы посчитан на стандартизованном train):

| Матрица | n строк | p признаков | Ранг XᵀX | Нулевых собственных чисел |
|---|---|---|---|---|
| весь train | 2225 | 5427 | **2224** | **3203** |
| обучающая часть фолда CV | 1780 | 5427 | **1779** | **3648** |
| один срез, возбуждение 350 нм | 2225 | 201 | 201 | 0 |

У матрицы 5427 × 5427 3203 собственных числа — ровно ноль. Матрица вырождена, обратной у неё нет.

### 3.3. Что это значит на практике: решений бесконечно много

Раз ранг меньше p, существуют ненулевые векторы v, для которых `Xv = 0`. Таких направлений 3203 (это размерность ядра X). Если β — решение, то и `β + v` — тоже решение:

```text
X(β + v) = Xβ + Xv = Xβ      ← предсказания на train те же, ошибка та же
```

Но на новых данных `X_new·v ≠ 0`, поэтому **предсказания на validation и test у этих решений разные**. Задача «найти МНК-решение» не имеет единственного ответа: одинаково хороших на train моделей бесконечно много, а предсказывают они по-разному.

Дальше хуже. Ранг центрированной X равен 2224 = n − 1, то есть её столбцы покрывают всё пространство центрированных векторов длины 2225. Значит, **любой y можно подогнать на train точно**: ошибка на train равна нулю, R² = 1 для любой цели, даже для случайного шума. В `experiments/6p_full_patience300/REPORT.md` это и зафиксировано: МНК на train даёт R² = 1 по всем целям.

### 3.4. Что тогда делает `sklearn.LinearRegression`

Она не падает, а молча выбирает одно из бесконечного числа решений — **решение с наименьшей нормой** ‖β‖ (через псевдообратную матрицу). Это не «МНК», а ещё одно, неявное условие, которое никто специально не выбирал. От него зависит, что модель предскажет на новых данных. Без стандартизации это решение ещё и зависит от масштаба каналов.

Для ППОП это приводило к двум проблемам:

- **Оценка на train не работает совсем.** Без любого одного канала из 5427 модель всё равно идеально подгоняется под train, поэтому MSE на train ≈ 0 для всех каналов. В старом прогоне `experiments/6p_tbs_per_ion` score каналов — порядка 1e-22, то есть численный шум. Рейтинг случайный.
- **Оценка на validation работает плохо.** В прогоне `experiments/6p_tbs_per_ion_valid` (Al, дисперсия y на validation 4.66) MSE модели-интерполятора была ≈ 3 на 5427 каналах, ≈ 71 на 3927 и **≈ 509 на 2427**. Последнее в сто раз хуже, чем просто предсказывать среднее. Ошибка особенно велика, когда число признаков близко к числу строк: это известный эффект «двойного спуска», когда модель только-только способна подогнаться под train и делает это ценой огромных весов.

### 3.5. Даже при p < n МНК на спектрах плохо обусловлен

Каналы EEM сильно скоррелированы: соседние по длине волны испускания каналы одного среза коррелируют с коэффициентом **0.998**. Поэтому даже там, где XᵀX формально обратима, она близка к вырожденной.

Мера этого — **число обусловленности**: отношение наибольшего собственного числа к наименьшему. Оно показывает, во сколько раз малое изменение данных может усилиться в весах.

| Матрица | Наибольшее λ | Наименьшее λ | Обусловленность без штрафа |
|---|---|---|---|
| весь train, 5427 каналов | 7.8·10⁶ | 0 (3203 штуки) | **бесконечность** |
| срез 350 нм, 201 канал | 3.9·10⁵ | 1.53 | **2.5·10⁵** |

Даже на одном срезе из 201 канала, где строк в 11 раз больше, чем признаков, веса МНК неустойчивы.

### 3.6. Что меняет Ridge

Ridge добавляет к ошибке штраф за большие веса:

```text
минимизировать  ‖y − Xβ‖² + alpha·‖β‖²
решение:        β = (XᵀX + alpha·I)⁻¹ Xᵀy
```

Матрица `A = XᵀX + alpha·I` при любом `alpha > 0` **положительно определена**, а значит обратима. Для любого ненулевого вектора v:

```text
vᵀAv = ‖Xv‖² + alpha·‖v‖² > 0
```

Даже если `Xv = 0` (направление из ядра), второе слагаемое положительно. На собственных числах это видно прямо: у A они равны `λ + alpha`, то есть **не меньше alpha**.

| Матрица | Обусловленность при alpha = 0 | alpha = 1 | alpha = 700 |
|---|---|---|---|
| весь train, 5427 каналов | бесконечность | 7.8·10⁶ | **1.1·10⁴** |
| обучающая часть фолда CV | бесконечность | 6.2·10⁶ | **8.9·10³** |
| срез 350 нм | 2.5·10⁵ | 1.5·10⁵ | **553** |

Смысл штрафа. Вдоль каждого собственного направления данных Ridge умножает «МНК-вес» на `λ / (λ + alpha)`:

- сильные направления (λ ≫ alpha) почти не трогаются. Например, первое λ = 7.8·10⁶: множитель 0.9999;
- слабые направления (λ ≪ alpha) гасятся. Например, 2000-е λ = 25.7: множитель 0.035;
- направления ядра (λ = 0) получают вес ровно 0. Из бесконечного множества решений Ridge выбирает одно, и выбор задан явным, понятным условием.

Поэтому с Ridge задача **корректна**: решение единственное, устойчивое, и модель без любого признака тоже определена однозначно. Это не обход ограничения, а другая, чуть смещённая модель, которая на этих данных предсказывает лучше. На validation по всем 5427 каналам оптимум alpha лежит между 390 (Cr) и 1000 (Co), у большинства ионов около 600–800; отсюда alpha = 700.

### 3.7. Когда МНК без штрафа всё-таки можно

Нужно, чтобы признаков было заметно меньше строк, и желательно, чтобы они не были почти копиями друг друга. Код это проверяет: при `alpha = 0` и `p ≥ n` он останавливается с объяснением, а при вырожденной XᵀX сообщает, что нужен `alpha > 0`.

Варианты для МНК, если он нужен:

1. Сначала сократить признаки Ridge-отбором до нескольких сотен, потом продолжить МНК.
2. Считать МНК по срезам возбуждения (201 канал на срез). Так делалось в `run_6p_ppop_all_slices.py`, но обусловленность и там около 2.5·10⁵.
3. Использовать Ridge с маленьким alpha как «почти МНК».

## 4. ППОП

### 4.1. Что делает метод

ППОП — обратный пакетный отбор. На каждой итерации при p оставшихся признаках:

1. Обучается **1 модель на всех p** признаках. Её ошибка — MSE.
2. Обучаются **p моделей**, каждая без одного признака j. Их ошибки — MSE₋ⱼ.
3. Для каждого признака считается **рост ошибки** без него: `Δⱼ = MSE₋ⱼ − MSE`.
   - большой Δⱼ: без признака модель заметно хуже, признак нужен;
   - Δⱼ около нуля: признак не нужен;
   - Δⱼ < 0: без признака модель даже лучше.
4. Выбрасывается пакет признаков с **наименьшими** Δⱼ.
5. Повторяется, пока признаки не кончатся.

Признак, продержавшийся дольше всех, получает ранг 1.

В медленной реализации шаг 2 означает p отдельных обучений с нуля. На первой итерации это 5427 регрессий на матрице 2225 × 5426, а за весь прогон с пакетом 1500 — 12 708 регрессий. Старый прогон `6p_tbs_per_ion_valid` занял **≈ 223 000 секунд (62 часа) на один ион** на сервере.

### 4.2. Главная идея: модель без признака j — та же задача с условием βⱼ = 0

После стандартизации (раздел 2) Ridge решает задачу

```text
минимизировать  ‖y − Xβ‖² + alpha·‖β‖²
решение:        β = A⁻¹ b,   где A = XᵀX + alpha·I,  b = Xᵀy
```

Модель без признака j — это та же задача, только вес j-го признака обязан быть нулём. Остальные признаки, их стандартизация и свободный член при этом не меняются:

```text
минимизировать  ‖y − Xβ‖² + alpha·‖β‖²   при условии  βⱼ = 0
```

Ответ такой задачи совпадает с переобучением модели на p − 1 признаках: столбец j с нулевым весом ни на что не влияет. Задачу с одним линейным условием решает множитель Лагранжа.

**Вывод.** Целевую функцию можно записать как `½βᵀAβ − bᵀβ` (плюс константа). Добавляем условие `eⱼᵀβ = 0`, где eⱼ — вектор с единицей на месте j:

```text
L(β, λ) = ½βᵀAβ − bᵀβ + λ·βⱼ
∂L/∂β = Aβ' − b + λ·eⱼ = 0   ⇒   β' = A⁻¹b − λ·A⁻¹eⱼ = β − λ·A⁻¹[:, j]
```

Множитель λ находим из условия `β'ⱼ = 0`:

```text
βⱼ − λ·A⁻¹[j, j] = 0   ⇒   λ = βⱼ / A⁻¹[j, j]
```

Итог — **точная формула** веса модели без признака j:

```text
β₋ⱼ = β − A⁻¹[:, j] · βⱼ / A⁻¹[j, j]
```

Проверка: j-я компонента равна `βⱼ − A⁻¹[j,j] · βⱼ / A⁻¹[j,j] = 0`.

Это не приближение. Формула даёт ровно те же веса, что и обучение с нуля, с точностью до ошибок округления. Нужны только обратная матрица A⁻¹ и полный вектор β, и то и другое — одно на все p признаков.

### 4.3. Ошибка на оценочной выборке сразу для всех признаков

Пусть на оценочной выборке (фолд CV или validation) стандартизованные признаки — `Xₑ`, центрированный y — `yₑ`. Обозначим:

```text
r  = yₑ − Xₑβ          остаток полной модели (вектор длины n_eval)
M  = Xₑ · A⁻¹          матрица n_eval × p
cⱼ = βⱼ / A⁻¹[j, j]    одно число на каждый признак
```

Предсказание модели без признака j:

```text
Xₑβ₋ⱼ = Xₑβ − Xₑ·A⁻¹[:, j]·cⱼ = Xₑβ − M[:, j]·cⱼ
```

Значит, её остаток `r₋ⱼ = r + M[:, j]·cⱼ`, а сумма квадратов ошибок:

```text
SSE₋ⱼ = ‖r + cⱼ·M[:, j]‖²
      = ‖r‖² + 2·cⱼ·(rᵀ M[:, j]) + cⱼ²·‖M[:, j]‖²
```

Для всех j это три векторные операции: `rᵀM` (вектор длины p), сумма квадратов по столбцам M (вектор длины p) и поэлементные действия с вектором c. В коде это метод `_Split.sse_without_each`.

**Последний признак.** Если остался один признак, формула даёт `β₋ⱼ = 0`, и предсказание равно среднему y по обучающей части. Это и есть правильная «модель без признаков», отдельный случай в коде не нужен.

### 4.4. Кросс-валидация: несколько пар «обучение — оценка»

В режиме `--score-on cv` train делится на 5 фолдов (`KFold(5, shuffle=True, random_state=0)`). Каждый фолд — отдельная пара «обучение (1780 строк) — оценка (445 строк)» со своей стандартизацией и своей матрицей A. SSE складываются по фолдам и делятся на 2225. Получаются MSE и MSE₋ⱼ по всему train. Каждая строка train ровно один раз побывала в оценке, поэтому все данные train используются, а validation в отборе не участвует.

В режиме `--score-on valid` пара одна: обучение на 2225 строках train, оценка на 600 строках validation.

### 4.5. Одна итерация целиком

1. **Один раз в начале** для каждой пары считаются `XᵀX` (5427 × 5427) и `Xᵀy` по всем каналам.
2. На итерации из `XᵀX` вырезается подматрица оставшихся p признаков, к диагонали прибавляется alpha.
3. Матрица обращается через разложение Холецкого (LAPACK `dpotrf` + `dpotri`). Это работает только для положительно определённой матрицы, см. 3.6.
4. По формулам 4.3 считаются `SSE` полной модели и `SSE₋ⱼ` для всех p признаков.
5. Суммы по парам делятся на число оценочных строк: MSE и MSE₋ⱼ, из них `Δⱼ = MSE₋ⱼ − MSE`.
6. Выбрасывается пакет с наименьшими Δⱼ. При равных Δⱼ раньше выбрасывается признак с меньшим по алфавиту именем, чтобы результат не зависел от случайностей.
7. Для каждого выброшенного признака запоминается его Δⱼ, это колонка `Score` рейтинга.

На следующей итерации обратная матрица считается заново для нового набора. Ошибки округления между итерациями не накапливаются.

### 4.6. Размер пакета

`--step` задаёт пакет так же, как в `sklearn.feature_selection.RFE`:

- целое число — фиксированный пакет (например, 1500);
- дробь из (0, 1) — доля от оставшихся признаков с округлением вверх, но не меньше одного признака. По умолчанию 0.1.

При 10% пакеты уменьшаются вместе с числом признаков: 543 из 5427, 489 из 4884, …, 23 из 226, потом по одному. Всего **66 итераций**. Подробная часть рейтинга оказывается в начале, где отбор важнее всего. С фиксированным пакетом 1500 итераций было бы 4, и первые 927 признаков ранжировала бы одна-единственная модель.

### 4.7. Рейтинг и файлы

- **`ranking.csv`**: `Feature`, `Group_Rank` (номер пакета, считая от последнего выброшенного: 1 — те, кто остался до конца), `Individual_Rank` (сквозной номер, 1 — лучший признак), `Score` (Δⱼ в момент выбрасывания). Внутри пакета первым идёт признак с наибольшим Δⱼ.
- **`history.csv`**: по одной строке на итерацию — сколько было признаков, MSE полной модели, сколько выброшено, сколько секунд заняло. По этой таблице видно, как меняется качество линейной модели по мере отбора.
- **`selection.json`**: название настройки и полное время.

Score разных итераций сравнивать между собой не стоит: Δⱼ считается относительно разных полных моделей.

### 4.8. Насколько это быстрее

Пусть n — число обучающих строк, p — число признаков.

| | Медленный ППОП | Быстрый ППОП |
|---|---|---|
| Работа на итерацию | p + 1 обучение, каждое ≈ n·p² + p³ | одно обращение ≈ p³ плюс произведение ≈ n_eval·p² |
| Порядок | ≈ p·(n·p² + p³) | ≈ p³ + n_eval·p² |

Выигрыш — примерно в p раз, на первых итерациях это тысячи раз.

Пример: полный быстрый ППОП на Cu (Ridge, alpha = 700, пакет 10%, 5-fold CV — впятеро больше работы, чем с validation) занял **156 секунд** на ноутбуке в один поток. Старый ППОП в режиме validation занимал **62 часа** на ион на сервере.

### 4.9. Как проверена точность

Тесты в `tests/test_linear_selection.py` сравнивают быстрый ППОП с честным переобучением sklearn:

- `test_ppop_scores_match_refitting_on_validation`: каждое Δⱼ совпадает с MSE модели `Pipeline(StandardScaler(), Ridge)`, обученной заново без признака j, минус MSE полной модели. Относительная точность 1e-7, и для Ridge, и для МНК;
- `test_ppop_cv_pools_folds_of_train`: то же для 5-fold CV;
- `test_ppop_matches_generic_refitting_class`: рейтинг совпадает с медленным `TrueBackwardFeatureSelection` с той же моделью;
- `test_ppop_fraction_packets_shrink`: пакеты при доле 0.25 идут 3, 3, 2, 1, 1, 1, 1 из 12 признаков;
- `test_ols_refuses_more_features_than_rows`: при alpha = 0 и p ≥ n код останавливается.

### 4.10. Что получилось на Cu

Ridge, alpha = 700, пакет 10%, 5-fold CV на train (`experiments/6p_ppop_ridge_a700_step0.1_cv5/Cu/history.csv`). Дисперсия Cu на train 4.55, R² ≈ 1 − MSE / 4.55 (оценка).

| Признаков | MSE по фолдам | R² ≈ |
|---|---|---|
| 5427 | 1.219 | 0.73 |
| 3203 | 0.883 | 0.81 |
| **2099** | **0.874** (минимум) | 0.81 |
| 656 | 0.933 | 0.79 |
| 226 | 1.123 | 0.75 |
| 75 | 1.495 | 0.67 |
| 24 | 2.101 | 0.54 |
| 6 | 3.026 | 0.33 |
| 1 | 4.145 | 0.09 |

Линейная модель с отобранными ~2000 каналами предсказывает лучше, чем на всех 5427: выброс ненужных каналов улучшил MSE с 1.22 до 0.87. Дальше качество падает медленно, примерно до 600 признаков. Как это переносится на персептрон, покажет кривая R² на test.

### 4.11. Ограничения

- Формула работает только для линейной модели с квадратичной ошибкой (МНК и Ridge). Для персептрона или нелинейных моделей остаётся медленный `TrueBackwardFeatureSelection`.
- При alpha = 0 нужна обратимая XᵀX (раздел 3.7).
- alpha одинаково для всех итераций. Оптимальное alpha для 100 признаков, скорее всего, меньше, чем для 5427. Подбирать alpha на каждой итерации — возможное улучшение.
- Память: на каждую пару хранится матрица 5427 × 5427 (≈ 235 МБ). При 5 фолдах это около 1.2 ГБ плюс рабочие копии.

## 5. RFE

### 5.1. Что делает метод

RFE (Recursive Feature Elimination) тоже выбрасывает признаки по одному или пакетами, но важность считает иначе:

1. Обучается **одна** модель Ridge на оставшихся признаках (только train).
2. Важность признака — **модуль его веса |βⱼ|** после стандартизации.
3. Выбрасывается признак (или пакет) с наименьшим |βⱼ|.
4. Повторяется, пока признаки не кончатся. Ранг 1 — последний оставшийся.

В отличие от ППОП, RFE не проверяет, как модель предсказывает без признака. Он смотрит только на веса обученной модели, поэтому validation и фолды ему не нужны.

Почему именно после стандартизации: вес βⱼ означает, насколько изменится предсказание, если признак j изменится на одно своё стандартное отклонение. Только при одном масштабе веса разных каналов сравнимы.

### 5.2. Классический и пакетный RFE

- **Классический (`--step 1`)**: по одному признаку за шаг. 5427 шагов, после каждого модель переобучается на оставшихся.
- **Пакетный (`--step 0.1`)**: 10% оставшихся за шаг, тот же размер пакета, что в ППОП (раздел 4.6). 66 шагов.

В пакете отбрасываются признаки с маленьким весом в **текущей** модели. Но после выбрасывания одного из них веса остальных перераспределяются: соседний канал мог «подхватить» его вклад. Классический RFE это учитывает после каждого признака, пакетный — только после пакета. Насколько это важно, показывает сравнение в 5.6.

### 5.3. Как сделать 5427 переобучений быстро: обновление обратной матрицы

Для весов нужна обратная матрица `A⁻¹ = (XᵀX + alpha·I)⁻¹` на текущем наборе: `β = A⁻¹·Xᵀy`. Обращать её заново на каждом из 5427 шагов — это 5427 операций порядка p³. Вместо этого используется формула для обратной матрицы без одной строки и столбца.

**Вывод.** Разобьём A на блок оставшихся признаков K и выбрасываемый признак j. Обратную A тоже разобьём на блоки и обозначим `B = A⁻¹`:

```text
A = | A_KK  A_Kj |        B = A⁻¹ = | B_KK  B_Kj |
    | A_jK  A_jj |                  | B_jK  B_jj |
```

Из формулы обращения блочной матрицы (через дополнение Шура) следует:

```text
(A_KK)⁻¹ = B_KK − B_Kj · B_jK / B_jj
```

Слева — обратная матрица для набора без признака j, ровно то, что нужно на следующем шаге. Справа — только элементы уже известной B. Это вычитание одной матрицы ранга 1, порядка p² операций вместо p³.

Для пакета D признаков формула та же, с блоком вместо числа:

```text
(A_KK)⁻¹ = B_KK − B_KD · (B_DD)⁻¹ · B_DK
```

**Детали реализации:**

- Формула применяется ко всей матрице на месте (BLAS `dger`), без копирования. Строка и столбец выброшенного признака при этом сами обращаются в ноль: `B_jK − B_jj · B_jK / B_jj = 0`. Поэтому его вес в `β = B·Xᵀy` автоматически становится нулём, и матрицу не нужно уменьшать на каждом шаге.
- Каждое такое обновление добавляет немного ошибки округления. Чтобы за тысячи шагов она не накопилась, **раз в 256 выброшенных признаков** матрица обращается заново по исходной `XᵀX` (параметр `refresh_every`). Заодно из неё удаляются нулевые строки и столбцы.
- В пакетном режиме при пакете больше 256 признаков матрица просто обращается заново на каждом шаге.

### 5.4. Скорость

| | Обычный классический RFE | Быстрый классический RFE |
|---|---|---|
| Работа на шаг | обучение Ridge ≈ n·p² + p³ | обновление ≈ p² |
| Всего | ≈ p·(n·p² + p³) | ≈ p³ (плюс ≈ 21 переобращение) |

На Cu: классический RFE — **155 секунд** (5427 шагов), пакетный 10% — **33 секунды** (66 шагов). Ноутбук, один поток.

### 5.5. Как проверена точность

- `test_rfe_step_one_matches_sklearn`: порядок выбрасывания совпадает с `sklearn.feature_selection.RFE(Ridge(alpha), step=1)` на стандартизованных данных. Проверено при переобращении матрицы на каждом шаге, раз в 3 шага и без переобращения, то есть формула обновления точна;
- `test_rfe_fraction_matches_refitting_loop`: пакетный режим совпадает с циклом, где Ridge честно переобучается на каждом шаге;
- `test_ols_refuses_more_features_than_rows`: при alpha = 0 и p ≥ n код останавливается.

### 5.6. Что получилось на Cu

Доля общих признаков среди первых k по рейтингу:

| Сравнение | k = 100 | k = 500 | k = 1000 |
|---|---|---|---|
| RFE классический и RFE пакет 10% | 0.85 | 0.94 | 0.95 |
| ППОП (CV) и RFE пакет 10% | 0.72 | 0.75 | 0.70 |
| ППОП (CV) и RFE классический | 0.63 | 0.75 | 0.72 |

Пакетный RFE почти повторяет классический, расхождения в основном среди первой сотни. ППОП и RFE совпадают примерно на 70%: это действительно разные критерии важности. Какой рейтинг лучше для персептрона, покажут кривые R² на test.

### 5.7. Слабые места RFE

- **Корреляция каналов.** Когда два соседних канала почти совпадают (корреляция 0.998), модель может поделить вес между ними как угодно. По отдельности |β| у обоих маленький, хотя вместе они важны. Ridge с alpha = 700 смягчает это (делит вес примерно поровну и устойчиво), но не убирает.
- **Нет проверки на новых данных.** Большой вес на train ещё не значит полезность на новых данных. ППОП это проверяет, RFE нет.
- **alpha фиксирован** (то же, что в 4.11).
- **МНК без штрафа** возможен только при признаков меньше строк (раздел 3.7).

## 6. ППОП и RFE рядом

| | ППОП | RFE |
|---|---|---|
| Важность признака | рост MSE без него на оценочной выборке | \|β\| в модели на train |
| Что использует | train (через CV) или validation | только train |
| Чем учитывает корреляцию | дубликат не нужен, пока в модели его пара | вес может делиться между дубликатами |
| Пакет по умолчанию | 10% от оставшихся | 1 (классический) |
| Время на ион (Cu, ноутбук, 1 поток) | 156 с (5-fold CV) | 155 с (классический), 33 с (10%) |
| МНК без штрафа | только при p < n | только при p < n |

## 7. Команды запуска

Каждая команда — для одного иона (`--ion Cu`, `Ni`, `Al`, `Co`, `Cr`, `NO3`). После рейтинга запускается персептрон на k = 500, 1000, …, 5000, 5427 с тремя seed.

```text
# ППОП, Ridge 700, пакет 10%, оценка 5-fold на train
python run_6p_linear_selection_per_ion.py --method ppop --alpha 700 --step 0.1 --score-on cv --ion Cu

# ППОП с оценкой на validation
python run_6p_linear_selection_per_ion.py --method ppop --alpha 700 --step 0.1 --score-on valid --ion Cu

# RFE классический и пакетный
python run_6p_linear_selection_per_ion.py --method rfe --alpha 700 --step 1 --ion Cu
python run_6p_linear_selection_per_ion.py --method rfe --alpha 700 --step 0.1 --ion Cu

# только рейтинг, без персептрона
python run_6p_linear_selection_per_ion.py --method rfe --step 1 --ion Cu --rank-only

# общий график по шести ионам, когда все готовы
python run_6p_linear_selection_per_ion.py --method rfe --step 1 --plot-only
```

Результаты лежат в `experiments/6p_<метод>_<модель>_step<пакет>[_cv5|_valid]/<ион>/`. Если `ranking.csv` уже есть, рейтинг не пересчитывается. Точки кривой, где все три seed уже посчитаны, пропускаются.

## 8. Открытые вопросы

1. **Где считать MSE для ППОП**: 5-fold на train (по умолчанию) или validation. См. раздел 1.
2. **МНК без штрафа**: на всех каналах невозможен (раздел 3). Нужен ли он после предварительного сокращения или по срезам?
3. **Сетка k**: с шагом 500 начало рейтинга не видно. Стоит добавить k = 100, 200, 300.
4. **alpha**: подбирать на каждой итерации или кросс-валидацией на train, а не на validation.
