# Геофизика (МТЗ): нормировки по строкам, ускоренный BSBS и ревизия старого кода

Подготовка к повторению на данных МТЗ того, что сделано для спектров 6P: нормировки каждого примера (по строкам) действуют только на отбор каналов, отбор — ускоренным BSBS, проверка — одной и той же моделью. Сами расчёты сетки ещё не запускались; на ноутбуке собраны кэши, подобран α и выполнен один пробный отбор (раздел 4).

## 2. Ошибки и нелогичности в старом коде для геофизики

| высокая | старый BSBS | Ошибка считалась либо на обучающей выборке (`cv=None`), либо через `cross_val_score` без перемешивания. Строки перемешаны, так что второе не страшно; первое меряет не обобщение | В новой сетке — 5-fold на train |
| средняя | d2 | valid 3000, test 6000, тогда как в d1 и в статье 6000 / 3000. Похоже, имена valid и test перепутаны | Уточнить. Пока использую файлы как названы |

## 3. Сетка

Код: `run_geo_selnorm_grid.py`, нормировки — `src/preprocessing/geo_norm.py`, тесты — `tests/test_geo_selnorm.py`.

**Нормировки по строкам** (каждого примера отдельно; аналог нормировок спектров). Профиль — 31 пикет одной части одной компоненты на одной частоте, блок — вся часть компоненты (13 × 31):

| Нормировка | Что делает |
|---|---|
| `raw` | без изменений |
| `profile_center` | минус среднее профиля: убирает общий уровень (одномерный фон), оставляет форму аномалии |
| `profile_scale` | деление профиля на его среднеквадратичное значение: убирает масштаб, сохраняет знак и форму |
| `profile_snv` | минус среднее и деление на стандартное отклонение профиля |
| `block_scale` | деление блока на его среднеквадратичное значение: выравнивает компоненты, сохраняет соотношения частот и пикетов |

Каналы внутри отбора всегда в z-score. Нормировки по каналам в сетку не входят: при почти нулевом α они на отбор почти не влияют.

**Протокол** — как в `6p_selnorm_grid`: нормировка строк влияет только на выбор каналов; Ridge, линейная регрессия и персептрон учатся на исходных данных с z-score. Есть и второй протокол (`input same`, проверка на нормированных данных, плюс представление импеданса модулем и фазой), но в основной набор заданий он не входит.

**Отбор:** ускоренный BSBS (`LinearPPOP`), пакет 10%, 5-fold на train. α подобран по validation на всех каналах: у всех трёх наборов оптимум на нижней границе сетки (10⁻⁶), для отбора взят α = 10⁻³ (раздел 4).

**Проверка:**
- Ridge и линейная регрессия: R² на validation и test при k = 10, 25, 50, 100, 250, 500, 750, 1000, 1500;
- персептрон: 1 скрытый слой из 32 нейронов, Adam lr 0.001, батч 128, ранний останов после 250 эпох без улучшения (как в статье PRIA), 3 инициализации; k = 10, 25, 50, 100, 250, 750 и все 2418 каналов.

**Задания** (`python run_geo_selnorm_grid.py --list-jobs --set …`):

| Набор заданий | Что внутри | Заданий |
|---|---|---|
| `prepare` | кэш и α для d1, d2, d3 | 6 |
| `d1`, `d2`, `d3` | 3 «все каналы» + 5 нормировок × 3 цели | по 18 |
| `d1_same` | второй протокол для d1 (по желанию) | 30 |

## 4. Проверка на ноутбуке

Собраны кэши трёх наборов (`experiments/geo_cache/`), подобран α (`experiments/geo_selnorm/<набор>/alpha.json`), выполнен один полный отбор на d1 (H3_8, без нормировки) и персептрон на 3 эпохи для оценки времени (`experiments/geo_selnorm_smoke/`).

| Шаг | Время (ноутбук, один поток) |
|---|---|
| кэш d1 из CSV | 26 с |
| подбор α (SVD 21000 × 2418) | ≈ 1 мин |
| полный отбор ускоренным BSBS, d1, 2418 признаков, 58 итераций | 87 с |
| персептрон, одна эпоха | 0.5 с при 100 каналах, 2.4 с при всех 2418 |

**Ridge на всех каналах, R² на validation:**

| Набор | H1_8 | H2_8 | H3_8 |
|---|---|---|---|
| d1 | 0.9999 | 0.9995 | 0.997 |
| d2 | 0.993 | 0.983 | 0.959 |
| d3 | 0.971 | 0.928 | 0.684 |

Данные d1 почти линейны. Отбор при этом важен: Ridge на первых 10 каналах BSBS для H3_8 даёт R² 0.54, на 25 — 0.84, на 50 — 0.96. Различия нормировок, скорее всего, проявятся при малых k. d3 заметно труднее, и на нём сравнение может быть показательнее.

**Почему α = 10⁻³, а не найденный 10⁻⁶.** XᵀX вырождена: эффективный ранг d1 около 1700 из 2418. При α = 10⁻⁶ число обусловленности около 10¹³, и быстрая формула расходится с переобучением на 10⁻⁵ (относительно); при 10⁻³ — на 10⁻⁸. На validation это почти ничего не стоит: 0.995 против 0.997 для H3_8 у d1.

## 5. Команды для сервера

**Код** (после пуша ветки):

```bash
cd /drive/larionov/geo_features && git pull
```

```bash
python -m pytest -q tests/test_geo_selnorm.py tests/test_linear_selection.py tests/test_selection_extensions.py
```

**Данные.** Если на сервере есть CSV в `Data/`:

```bash
python run_geo_selnorm_grid.py --list-jobs --set prepare > geo_prepare.txt && xargs -L 1 -a geo_prepare.txt python run_geo_selnorm_grid.py --job
```

Иначе скопировать с ноутбука `experiments/geo_cache/*.npz` (d1 и d2 по ≈ 580 МБ, d3 ≈ 190 МБ) и `experiments/geo_selnorm/d1|d2|d3/alpha.json` в те же папки.

**Сетка** (в tmux): сначала только отбор и линейная проверка — около 10 минут на набор:

```bash
mkdir -p logs/geo && (for s in d1 d2 d3; do python run_geo_selnorm_grid.py --list-jobs --set $s; done) > geo_jobs.txt && xargs -P 8 -L 1 -a geo_jobs.txt bash -c 'python run_geo_selnorm_grid.py --no-perceptron --job "$@" > "logs/geo/$(echo "$@" | tr " " "_").log" 2>&1' _
```

Затем персептрон — те же задания без `--no-perceptron` (готовый отбор переиспользуется):

```bash
xargs -P 8 -L 1 -a geo_jobs.txt bash -c 'python run_geo_selnorm_grid.py --job "$@" >> "logs/geo/$(echo "$@" | tr " " "_").log" 2>&1' _
```

Оценка: около 3–4 часов на задание с отбором (6 значений k × 3 инициализации, порядка 1000 эпох) и 2–3 часа на «все каналы». На 8 ядрах это около 7–8 часов на d1 или d2 и около 3 на d3, всего около 18 часов на три набора.

**Результаты:**

```bash
python run_geo_selnorm_grid.py --summary && tar czf geo_results.tgz --exclude='learning_curves' --exclude='training.log' experiments/geo_selnorm logs/geo
```
