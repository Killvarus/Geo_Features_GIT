# PLS: что это, как из признаков получается толщина слоя, какие были результаты

Этот файл — подробное объяснение **Partial Least Squares** в нашем проекте. Код: `src/preprocessing/pls.py`, `src/experiment/pls_experiment.py`, запуск `run_pls_experiment.py`. Результаты: `experiments/2026-09-04_pls/`.

Главное отличие от PCA, агрегации и вейвлетов: **PLS сам предсказывает толщину слоя**. Нейросеть (OLP) здесь не используется.

---

## 1. С какой задачей мы работаем

Обратная задача МТЗ: по электромагнитному отклику на поверхности восстановить толщины слоёв модели.

Каждая **строка CSV** — один синтетический разрез (один объект). У него есть:

- **признаки X** — поле на разных частотах и пикетах;
- **цели y** — толщины слоёв в выбранной точке профиля.

Мы всегда берём **один** таргет за прогон: `H1_8`, `H2_8` или `H3_8`. Это толщина 1-го, 2-го или 3-го слоя на **8-м пикете** целевой сетки.

Три выборки (одинаковые 2418 признаков, разные «сложности»):

| Короткое имя | Файлы | Train / valid / test |
|---|---|---|
| old (Difficult_1) | `mtsgrvmgn_trn/vld/tst.csv` | 21000 / 6000 / 3000 |
| train3 (Difficult_2) | `train_3` / `valid_3` / `test_3` | 21000 / 3000 / 6000 |
| train3_1 (Difficult_3) | `train_3_1` / `valid_3_1` / `test_3_1` | 7000 / 1000 / 2000 |

H3 на train3_1 — самый трудный слой: мало данных и самая «глубокая» толщина.

## 2. Что означают исходные признаки

Имя колонки разбирается так:

```text
{RE|IM}{YX|XY|HX}{частота}_{пикет}
пример: REYX5_12
```

| Часть | Значение |
|---|---|
| `RE` / `IM` | действительная и мнимая части комплексного отклика |
| `YX`, `XY` | поляризации импеданса (E_y/H_x и E_x/H_y) |
| `HX` | связанный магнитный канал (вертикальная передаточная функция в нашей разметке) |
| число после поляризации, 1…13 | индекс частоты зондирования (не герцы в имени, а номер из набора 13 частот) |
| число после `_`, 1…31 | пикет профиля |

Итого: 2 × 3 × 13 × 31 = **2418** чисел на объект. Это уже **не** сырой временной ряд \(E(t), H(t)\), а частотная характеристика вдоль профиля.

Физически соседние частоты и соседние пикеты сильно коррелированы: поле «гладкое». Из-за этого 2418 координат избыточны. PCA ищет оси максимальной дисперсии **только в X**. PLS ищет оси, которые ещё и **связаны с y**.

Все колонки, имя которых начинается с `H`, из X выкидываются. В обучение не попадают ни `H1_8`, ни соседние `H1_7`, ни прочие толщины — только запрошенный таргет как y.

---

## 3. Что такое PLS (идея)

PCA отвечает на вопрос: «какие линейные комбинации признаков сильнее всего меняются от объекта к объекту?»  
PLS отвечает: «какие линейные комбинации признаков **лучше всего предсказывают толщину слоя**?»

Пусть \(X\) — матрица \(n \times 2418\) (объекты × признаки), \(y\) — вектор толщин \(n \times 1\).

PLS строит \(k\) **латентных компонент** (скрытых координат). Первая компонента — направление \(w_1\) в пространстве признаков такое, что проекция \(t_1 = X w_1\) максимально **коварирует** с \(y\) (точнее, с проекцией \(y\)). Следующие компоненты ортогональны предыдущим и ловят остаток связи с \(y\).

Интуиция:

- признак, который сильно гуляет, но **не связан** с H3, для PLS почти бесполезен;
- слабый, но стабильно коррелированный с H3 признак — полезен;
- коррелированные блоки (все частоты одной поляризации) схлопываются в одну-две компоненты, а не занимают сотни осей.

Поэтому при малом \(k\) PLS обычно сильнее PCA+нейросети: он сразу целится в y.

В литературе это NIPALS / SIMPLS. У нас `sklearn.cross_decomposition.PLSRegression`.

## 4. Как в коде формируются «признаки» PLS и откуда берётся ответ

Важно: колонки `PLS1, PLS2, …` в `transform()` — это **не то, на чём мы считаем метрики**. Это проекции (scores). Конечная толщина считается методом `predict()`.

### 4.1. Подготовка (fit только на train)

1. Из train/valid/test берутся все колонки, которые **не** начинаются с `H` → \(X\) (2418 штук).
2. NaN в X заполняются **средним по train** (`SimpleImputer`).
3. X стандартизуется: вычитается среднее train, делится на std train (`StandardScaler` по признакам).
4. y (например `H3_8`) тоже стандартизуется своим scaler: среднее и std **толщины на train**.

Без стандартизации признаки с большой амплитудой (например одна поляризация) забили бы ковариацию.

`PLSRegression(..., scale=False)` — внутри sklearn второй раз не масштабирует, это уже сделали мы.

### 4.2. Обучение PLS на train

```text
transformer.fit(X_train, y_train)
```

Алгоритм (схема NIPALS для одного y):

1. Найти веса \(w\), максимизирующие \(\mathrm{cov}(Xw,\, y)\).
2. Счёт (score) \(t = Xw\).
3. Загрузить, как \(t\) восстанавливает X и y (loadings).
4. Вычесть из X и y объяснённую часть, повторить для следующей компоненты.

После \(k\) компонент есть матрица регрессии \(B\) размера \(2418 \times 1\) (в стандартизованных единицах):

\[
\hat y_{\mathrm{scaled}} = X_{\mathrm{scaled}}\, B.
\]

Sklearn прячет \(B\) внутри `pls.coef_`. Нам это не нужно руками: вызываем `predict`.

Число компонент \(k\) мы задаём снаружи: 16, 64, 256, 512, 1024, 1536, 2048. Больше, чем \(\min(2418, n_{\mathrm{train}})\), взять нельзя.

### 4.3. Как получается конечный результат (valid/test)

Для **нового** объекта (строка test):

1. Те же 2418 сырых признаков.
2. Imputer и scaler **train** (не test — иначе утечка).
3. `pls.predict(X_scaled)` → толщина в **стандартизованных** единицах.
4. `scaler_y.inverse_transform(...)` → толщина в **метрах (исходный масштаб CSV)**.

Это и есть ответ модели. Никакого второго этапа с OLP нет.

Valid нужен только чтобы смотреть метрики на отложенной выборке; в `fit` он не входит. Early stopping нет: PLS либо сошёлся по NIPALS, либо упёрся в `max_iter`.

### 4.4. Чего PLS не делает

- Не пересобирает сетку частота × пикет (в отличие от вейвлетов).
- Не усредняет соседние частоты (в отличие от агрегации).
- Не обучает нейросеть.
- Не запускает 3 random seed: при фиксированных данных ответ детерминированный. Поэтому в `summary.json` поле `r2_std` почти всегда 0 — это не «идеальная стабильность», а **один** fit.

## 5. Что означают «PLS-компоненты» как признаки

Если вызвать `transform()`, каждый объект сжимается в вектор \((t_1,\ldots,t_k)\):

- `PLS1` — самая «полезная для y» линейная смесь всех 2418 каналов;
- `PLS2` — следующая, ортогональная к первой, и т.д.

Интерпретация `PLS1` «это частота 7» невозможна напрямую: в смеси участвуют все RE/IM и все пикеты, просто с разными весами. Веса (`x_weights_`) можно смотреть, но в отчёт мы их не выгружали.

Метрика `variance_explained` в summary — **доля дисперсии X**, которую несут scores, а не доля дисперсии y. Для PLS это грубая диагностика «насколько сжался X», не качество прогноза. Качество — R² / MSE / MAE / Pearson на test.

---

## 6. Как считаются метрики

После `predict` на test:

- **R²** — какая доля дисперсии толщины объяснена (\(1\) = идеал, \(0\) = как среднее, \(<0\) = хуже константы);
- **MSE / MAE** — квадратичная и абсолютная ошибка в единицах толщины;
- **Pearson** — линейная корреляция \(\hat y\) и \(y\).

Считаем только test (в `r2_mean`). Train/valid пишутся в `all_iterations_data` у summary, чтобы видеть переобучение: при большом \(k\) train R² может быть почти 1, test — ниже.

## 7. Результаты полного прогона

Сетка: \(k \in \{16, 64, 256, 512, 1024, 1536, 2048\}\), все три датасета, все три таргета. Папка `experiments/2026-09-04_pls/`.

Test R² (лучшие \(k\) в скобках по смыслу «выход на плато»):

| Таргет | old | train3 | train3_1 |
|---|---:|---:|---:|
| H1_8 | ~1.000 (уже с 256) | 0.993 (1024) | 0.966 (512) |
| H2_8 | ~1.000 (с 256) | 0.983 (1024) | 0.927 (256) |
| H3_8 | 0.9975 (2048) | 0.962 (1536) | **0.6735 (1536)** |

Полная сетка по \(k\) для H3_8:

| k | old | train3 | train3_1 |
|---:|---:|---:|---:|
| 16 | 0.537 | 0.414 | 0.249 |
| 64 | 0.894 | 0.813 | 0.399 |
| 256 | 0.995 | 0.948 | 0.569 |
| 512 | 0.997 | 0.957 | 0.632 |
| 1024 | 0.997 | 0.960 | 0.659 |
| 1536 | 0.997 | 0.962 | 0.674 |
| 2048 | 0.998 | 0.962 | 0.670 |

Что это значит.

1. **Малое k уже много даёт.** 64 компоненты (сжатие ~38×) на old/H3 дают R² 0.89. PCA с 64 компонентами на том же old/H3 — только 0.63, потому что PCA не смотрит на y.
2. **Плато.** После 256–512 добавление компонент почти не улучшает test. «Все 2418» не нужны.
3. **train3_1 / H3 — потолок ~0.67.** Это не баг PLS: тот же слой для PCA+OLP выходит ~0.62 даже при 2048 компонентах. Данных мало, связь поля с H3 слабее.
4. На H1/H2 PLS почти идеально на old и train3: задача для верхних слоёв линейно хорошо обусловлена.

Сравнение с PCA+OLP (боевой протокол, hidden=32): на **трудном** H3 PLS обычно **выше** при том же порядке числа компонент, потому что компоненты сразу регрессионные. На лёгких H1/H2 оба метода выходят в 0.99+, разница косметическая.

## 9. Короткий чеклист «как читать PLS»

1. Признаки на входе — те же 2418 комплексных откликов, что у всех методов.
2. PLS **учится на парах (X, y) только train**.
3. Ответ — линейная регрессия в пространстве \(k\) латентных компонент, потом обратное масштабирование y.
4. Нейросети нет.
5. Больше \(k\) ≠ всегда лучше на test; смотреть плато на графике R² vs k.
6. `r2_std = 0` здесь нормально: один детерминированный fit, не три seed OLP.
