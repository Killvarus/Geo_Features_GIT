# Методы нормировки в экспериментах 6P: как они получаются

Описание всех нормировок, которые использовались в сетке `run_6p_norm_grid.py`: что делает каждая, по каким формулам считается, на каких данных берутся статистики и где лежит код. Для каждой — маленький числовой пример.

Результаты сравнения нормировок — в `experiments/6p_norm_grid/REPORT.md`, их физический смысл и связь с alpha — в `experiments/6p_norm_grid/NORMALIZATIONS.md`.

| Что | Код |
|---|---|
| Нормировки спектров | `src/preprocessing/spectrum_norm.py`, функция `normalize_spectra` |
| Нормировки каналов | `src/models/linear_selection.py`, функции `scale_channels` и `scale_only` |
| Как всё собирается в сетку | `run_6p_norm_grid.py`, функции `load`, `run_rank`, `linear_check` |
| Проверки | `tests/test_spectrum_norm.py`, `tests/test_linear_selection.py`, `tests/test_norm_grid.py` |

## 1. Данные

Таблица 3125 × 5427:

- **строка** — один спектр (образец);
- **столбец** — один канал, пара длин волн «возбуждение, испускание»: 27 возбуждений (280, 285, …, 410 нм) × 201 испускание (375, 376, …, 575 нм);
- в строке каналы идут блоками: сначала 201 канал возбуждения 280 нм, потом 201 канал 285 нм и так далее. Это проверено по данным: корреляция соседних колонок падает ровно на границах блоков по 201.

Разбиение по порядку строк: **train** — первые 2225, **validation** — следующие 600, **test** — последние 300.

Нормировать можно в двух направлениях:

- **по строкам** (нормировки спектров) — каждый спектр отдельно, используется только он сам;
- **по столбцам** (нормировки каналов) — каждый канал по всем спектрам; статистики (среднее, разброс) берутся **только по train** и применяются ко всем строкам.

## 2. Каналы рассеяния — исключаются из статистик спектра

На карте есть линии рэлеевского рассеяния. Их интенсивность намного выше флуоресценции (в отдельных спектрах до 95 900 против ~170 в вершине пика). Если брать по ним максимум или площадь, нормировка будет нормировкой на рассеяние.

Поэтому все статистики спектра (максимум, сумма, среднее, отклонение) считаются **только по каналам вне линий рассеяния** — маска `fluorescence_mask()`:

```text
рассеяние первого порядка:  |испускание − возбуждение|     ≤ 10 нм   — 160 каналов
рассеяние второго порядка:  |испускание − 2·возбуждение|   ≤ 15 нм   —  64 канала
в статистики идут остальные 5203 канала из 5427
```

Сами каналы рассеяния из данных **не удаляются**: делятся на то же число, что и остальные, и остаются доступны отбору.

Во всех примерах ниже последний канал (значение 50) — рассеяние, в статистики он не входит.

---

## 3. Нормировки спектров (по строкам)

Обозначения: x — один спектр, M — каналы вне линий рассеяния.

### 3.1. `raw` — без нормировки

```text
x' = x
```

Данные как есть. Так считались все эксперименты до сетки.

### 3.2. `max` — на максимум

```text
x' = x / max_{j ∈ M} x_j
```

1. Найти максимум спектра среди каналов вне рассеяния. Почти всегда это вершина пика флуоресценции (возбуждение ≈ 355 нм, испускание ≈ 450 нм).
2. Поделить на него **все** каналы спектра.

Пример: x = (4, 10, 6, −1, 2, **50**). Максимум вне рассеяния — 10.

```text
x' = (0.4, 1, 0.6, −0.1, 0.2, 5)
```

После нормировки вершина пика у всех спектров равна 1: разница в общей яркости убрана, остаётся форма. Каналы рассеяния могут оказаться больше 1 — это нормально.

### 3.3. `area` — на площадь

```text
x' = x / Σ_{j ∈ M} x_j
```

1. Сложить все каналы вне рассеяния.
2. Поделить на эту сумму все каналы.

Пример: сумма 4 + 10 + 6 − 1 + 2 = 21.

```text
x' = (0.190, 0.476, 0.286, −0.048, 0.095, 2.381)
```

По смыслу то же, что «на максимум», но статистика собирается со всего спектра и меньше зависит от шума в одной точке. Значения после неё очень маленькие: на реальных данных вершина пика ≈ 10⁻³.

### 3.4. `snv` — Standard Normal Variate

```text
x' = (x − mean_{j ∈ M} x_j) / std_{j ∈ M} x_j
```

1. Найти среднее и стандартное отклонение спектра по каналам вне рассеяния.
2. Из всех каналов вычесть среднее и поделить на отклонение.

Пример: среднее (4 + 10 + 6 − 1 + 2) / 5 = 4.2, отклонение 3.709.

```text
x' = (−0.054, 1.564, 0.485, −1.402, −0.593, 12.347)
```

Убирает и множитель (яркость), и сдвиг (общий фон). Не путать с z-score каналов: SNV считается **по строке** (по одному спектру), z-score — **по столбцу** (по одному каналу на всех спектрах train).

### 3.5. `raman` — на пик комбинационного рассеяния воды

```text
h = mean(испускание 382–386 нм) − ( mean(375–377 нм) + mean(391–393 нм) ) / 2
    — всё в строке возбуждения 340 нм

x' = x / max(h, P1),   P1 = 1-й процентиль h по спектрам train
```

1. Взять строку возбуждения 340 нм.
2. Высота пика: среднее по испусканию 382–386 нм минус линейный фон (среднее двух соседних участков, 375–377 и 391–393 нм).
3. Если высота меньше 1-го процентиля высот по train (4.74 на наших данных), заменить её этим порогом. Порог срабатывает у 1.1% спектров.
4. Поделить весь спектр на высоту.

Почему именно так:
- пик воды смещён на 3400 см⁻¹ от возбуждения. При возбуждении 340 нм он приходится на испускание ≈ 384 нм;
- при 330–335 нм пик выходит за край сетки (испускание < 375 нм), при 345–350 нм сливается с флуоресценцией. При 340 нм он виден отдельно: в среднем 15.8 против 3.1 и 8.1 по бокам;
- медианная высота — 9.3, разброс от спектра к спектру — 15%;
- у отдельных спектров высота около нуля (минимум −0.37), без порога деление раздуло бы их в сотни раз.

Порог — единственный параметр нормировок спектров, который берётся по выборке. Он считается **только по train**.

### 3.6. `row_max` — каждая строка возбуждения на свой максимум модуля

```text
для каждой строки возбуждения e (201 канал):
x'_e = x_e / max_{j ∈ M, j в строке e} |x_j|
```

1. Разбить спектр на 27 строк возбуждения по 201 каналу.
2. В каждой строке найти максимум **модуля** по каналам вне рассеяния.
3. Поделить строку на него.

Пример для двух строк по 3 канала:

```text
строка «шумная»:  (−0.5, 0.8, −1.2)  → максимум модуля 1.2  → (−0.417, 0.667, −1)
строка с сигналом: (20, 40, 10)       → максимум модуля 40   → (0.5, 1, 0.25)
```

Модуль нужен, потому что в строках 280–300 нм почти один шум, и обычный максимум там бывает отрицательным (до −9). Деление на него перевернуло бы строку. Побочный эффект виден в примере: шумная строка растягивается до того же масштаба (до 1), что и строка с сигналом, а соотношение яркости между строками теряется.

### 3.7. Защита от деления на неположительное

`max`, `area` и `row_max` проверяют знаменатель. Если у какой-то строки он ≤ 0, нормировка падает с ошибкой «… спектра ≤ 0 у N строк, нормировка не определена». Иначе такой спектр поменял бы знак или улетел в бесконечность без предупреждения. `raman` проверяет, что порог P1 положителен.

## 4. Нормировки каналов (по столбцам)

Для каждого канала j по строкам **train** считаются сдвиг и масштаб, затем:

```text
z_j = (x_j − сдвиг_j) / масштаб_j
```

Статистики берутся только по train. Внутри ППОП — по обучающей части каждого фолда кросс-валидации, и применяются к его оценочной части. Если масштаб канала равен 0 (канал постоянный), он заменяется на 1.

| Нормировка | Сдвиг | Масштаб |
|---|---|---|
| `zscore` | среднее канала | стандартное отклонение (как `StandardScaler`) |
| `pareto` | среднее канала | корень из стандартного отклонения |
| `robust` | среднее канала | межквартильный размах: 75-й минус 25-й процентиль |
| `center` | среднее канала | 1 (масштаб исходный) |

Пример: 4 спектра, 2 канала.

```text
           канал A   канал B
спектр 1      1        100
спектр 2      3        300
спектр 3      2        150
спектр 4      6        250

среднее        3        200
отклонение     1.871    79.06
IQR            2        125
```

| Спектр | zscore A, B | pareto A, B | robust A, B | center A, B |
|---|---|---|---|---|
| 1 | −1.07, −1.27 | −1.46, −11.25 | −1.0, −0.8 | −2, −100 |
| 2 | 0, 1.27 | 0, 11.25 | 0, 0.8 | 0, 100 |
| 3 | −0.53, −0.63 | −0.73, −5.62 | −0.5, −0.4 | −1, −50 |
| 4 | 1.60, 0.63 | 2.19, 5.62 | 1.5, 0.4 | 3, 50 |

Видно, что делает каждая:
- **z-score** выравнивает каналы полностью: оба в одном масштабе;
- **Pareto** — частично: канал B, у которого разброс больше, остаётся «громче» A;
- **robust** близок к z-score, но масштаб не зависит от выбросов;
- **center** оставляет исходный масштаб: B в 50 раз «громче» A.

Почему у `robust` сдвиг — среднее, а не медиана. Для Ridge со свободным членом сдвиг канала ни на что не влияет, важен только масштаб. А быстрые формулы ППОП и RFE требуют, чтобы каналы были центрированы средним.

«Без нормировки каналов» отдельно не считается: у Ridge со свободным членом вычитание среднего ничего не меняет, поэтому рейтинги совпали бы с `center`.

## 5. Как нормировки собираются вместе

### 5.1. Прямой порядок (основная сетка): сначала спектры, потом каналы

```text
исходные данные
  → нормировка спектров (raw, max, area, snv, raman, row_max)       — меняет сами данные
  → отбор: внутри ППОП или RFE нормировка каналов
           (zscore, pareto, robust, center) + Ridge alpha = 700     — даёт рейтинг каналов
  → проверка: те же нормированные спектры, первые k каналов,
              z-score каналов (всегда) → Ridge, МНК, персептрон
```

Папки: `experiments/6p_norm_grid/<спектр>__<каналы>/<метод>/<ион>/`.

### 5.2. Обратный порядок (`chfirst`): сначала каналы, потом спектры

```text
исходные данные
  → каждый канал делится на свой масштаб по train БЕЗ вычитания среднего
    (scale_only: zscore — на std, pareto — на корень из std, robust — на IQR)
  → нормировка спектров (max, area, snv, raman, row_max)
  → отбор без повторного масштабирования (только центрирование)
  → проверка как в прямом порядке
```

Пример `scale_only` для канала A из таблицы выше (деление на отклонение 1.871 без вычитания среднего): (1, 3, 2, 6) → (0.53, 1.60, 1.07, 3.21).

Почему без вычитания среднего: после центрирования сумма спектра близка к нулю (≤ 0 у 63–65% спектров), а максимум и высота пика воды уходят в ноль или в минус. Нормировки на площадь, максимум и пик воды теряют смысл.

Исключены две комбинации: `zscore` + `area` и `robust` + `area`. После деления на масштаб шумовые каналы с малым разбросом раздуваются, и у части спектров сумма становится ≤ 0.

Итого 13 комбинаций. Папки: `experiments/6p_norm_grid/<спектр>__<каналы>__chfirst/<метод>/<ион>/`.

### 5.3. Итоговая модель — всегда z-score

Во всех проверках (Ridge, обычная регрессия, персептрон, в том числе на всех 5427 каналах без отбора) каналы приводятся к z-score по train. Ridge и МНК — через `StandardScaler` в конвейере, персептрон — внутри своей функции обучения. Нормировка каналов из сетки влияет только на то, **какие** каналы выберет отбор.

---

## 6. Что из этого берётся по train

| Величина | По каким данным |
|---|---|
| Максимум, площадь, среднее и отклонение спектра (`max`, `area`, `snv`, `row_max`) | только сам спектр |
| Порог высоты пика воды (`raman`) | train |
| Сдвиг и масштаб каналов (`zscore`, `pareto`, `robust`, `center`, `scale_only`) | train; внутри ППОП — обучающая часть каждого фолда |
| z-score перед итоговой моделью | train |

Ничего из validation и test в статистики нормировок не попадает.
